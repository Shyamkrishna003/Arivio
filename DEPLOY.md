# Deploying Nirnavi for free

The app is a Vite SPA plus a FastAPI backend that needs a real Postgres, the
`tesseract` binary and a writable directory. That rules out running the backend
on a serverless platform, so it splits across three free tiers:

| Piece | Where | Free tier |
|---|---|---|
| Frontend + `/api` proxy | **Vercel** | Hobby. Non-commercial use only |
| Backend (Docker) | **Render** | 512MB, sleeps after 15min idle → ~50s cold start |
| Postgres | **Neon** | 0.5GB, autosuspends and wakes itself in ~1s |
| Redis | **Upstash** | Optional; 10k commands/day |

Nothing here needs a card.

**Why Neon over Supabase.** Both work, and Supabase's table editor is nicer to
live in. But a free Supabase project *pauses* after 7 days idle and needs a
click in the dashboard to come back, so a demo after a quiet week is down until
you notice. Neon wakes on the first connection. If you do pick Supabase, use the
**session-mode** pooler on port 5432; on the transaction pooler (6543) you must
also set `DATABASE_PREPARED_STATEMENTS=false`, or asyncpg fails on prepared
statements in a way that looks nothing like a configuration problem.

Order matters: the database exists before the backend can migrate against it,
and the backend has a URL before Vercel can proxy to it.

## 1. Postgres — Neon

Create a project, then copy the **pooled** connection string. Paste it into
`DATABASE_URL` as given — `?sslmode=require&channel_binding=require` included.
[app/db/url.py](backend/app/db/url.py) rewrites the scheme to name asyncpg and
converts the TLS parameters, which asyncpg would otherwise reject.

No extension setup is needed: the only one Nirnavi uses is `pg_trgm`, and
[the trigram migration](backend/alembic/versions/a7c31f9d5b60_add_trigram_product_search.py)
creates it. There are no `vector` columns yet, so pgvector is not required.

## 2. Redis — Upstash

Create a database and copy the `rediss://` URL into `REDIS_URL`. Skippable —
[app/core/cache.py](backend/app/core/cache.py) turns every failure into a cache
miss — but without it a reload on the OCR confirmation screen loses the pending
extraction and the photo has to be re-read.

## 3. Backend — Render

**New > Blueprint**, point it at this repo. [render.yaml](render.yaml) declares
the service, so the only work is filling in the values it marks `sync: false`:

| Variable | Value |
|---|---|
| `DATABASE_URL` | from step 1 |
| `REDIS_URL` | from step 2 |
| `CORS_ORIGINS` | `https://<your-app>.vercel.app` — comma-separated or a JSON array |
| `HEALTH_ENCRYPTION_KEY` | `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` |
| `GEMINI_API_KEY` | [aistudio.google.com/apikey](https://aistudio.google.com/apikey) — free tier |
| `OPEN_FOOD_FACTS_USER_AGENT` | `Nirnavi/0.1 (your-email@example.com)` |

`SECRET_KEY` is generated by Render. Don't rotate it later — every issued JWT
becomes invalid and every user is logged out.

Two things about `HEALTH_ENCRYPTION_KEY`: leaving it blank is a supported
choice, and makes every health endpoint answer 503 rather than storing lab
results in plaintext. And once it has encrypted anything, losing it makes that
data permanently unreadable — back it up like a password.

On boot [start.sh](backend/start.sh) runs `alembic upgrade head` and then
uvicorn on Render's `$PORT`. Watch the first deploy's logs: a bad
`DATABASE_URL` surfaces there, before the health check ever passes.

## 4. Frontend — Vercel

Import the repo with **Root Directory = `frontend`**. The Vite preset picks up
[vercel.json](frontend/vercel.json) on its own.

Two steps, both required:

1. **Edit [vercel.json](frontend/vercel.json)** — replace both
   `https://nirnavi-backend.onrender.com` placeholders with your real Render URL.
   Vercel does not interpolate environment variables into rewrite destinations,
   so this genuinely has to be hardcoded.
2. **Set `VITE_API_URL=/api/v1`** as a build-time environment variable. A
   relative value is the point: it makes the browser call Vercel, which proxies
   to Render, so everything is same-origin and CORS never applies. Leaving it
   unset falls back to `http://<hostname>:8000/api/v1`
   ([api.ts:6](frontend/src/services/api.ts#L6)), which is correct locally and
   broken in production.

The third rewrite sends unmatched paths to `index.html`, which
`BrowserRouter` ([App.tsx:69](frontend/src/App.tsx#L69)) needs — without it a
refresh on `/scan` is a 404. Rewrites only apply after the static file lookup
misses, so real assets are unaffected.

## What to expect from the free tiers

**A ~50s first request.** Render free sleeps after 15 minutes idle, and the wake
includes the migration step. Everything after that is normal speed. A cron job
pinging `/health` every 10 minutes hides it, at the cost of your 750 monthly
instance-hours — which is roughly all of them, so it only works if this is the
only service in the account.

**Uploaded label photos vanish on restart.** The container's disk is ephemeral,
so `/uploads/<hash>.jpg` — written by
[ocr/storage.py](backend/app/ocr/storage.py) and served at
[main.py:91](backend/app/main.py#L91) — is gone after every sleep or deploy. The
OCR flow still works, because it re-reads the image the user just uploaded; only
older photos 404. The real fix is object storage, which changes the URL those
are stored with and nothing else.

**Neon sleeps too**, but transparently: `pool_pre_ping` and `pool_recycle=300`
in [session.py](backend/app/db/session.py) exist so a suspended database costs
one retried connection rather than a failed request.

## A custom domain

Vercel gives you `<project>.vercel.app` with HTTPS, which is enough to launch.
For something shorter: Cloudflare Registrar sells domains at wholesale
(~$5–10/yr) with no markup, which is the cheapest honest option. Genuinely free
are the GitHub Student Developer Pack's `.me` for a year, or a community
subdomain from `is-a.dev` / `js.org` / `eu.org` — those are PR-reviewed and take
a few days. Freenom's `.tk` and `.ml` are dead; skip them.

Once you have one, add it in Vercel's domain settings and point DNS there. The
backend keeps its `onrender.com` hostname — nothing reaches it directly except
through the proxy.
